账户模型

Account与AccountInfo的区别

类型 说明
Account 链上真实账户，存储结构体、余额等。
AccountInfo 程序运行时传入的账户引用，包含账户的地址、数据、余额等信息。

在 Solana 程序里你不能“新建变量”来保存状态，只能操作这些 AccountInfo 代表的账户数据。

CPI

CPI（Cross-Program Invocation）是指：一个程序调用另一个程序中的指令。

例如，你的 AMM 合约需要调用 SPL Token 的 transfer 指令完成代币转账：

CPI 是 Solana 合约之间“模块化协作”的基础。

rent、lamports、PDA

Solana 的原生代币 SOL，最小单位是 lamports（1 SOL = 10^9 lamports）。

账户要存活在链上，必须有一定的 lamports 余额。

rent（租金）

Solana 的账户系统不是免费存储的，每个账户都要为它的数据大小抵押 lamports（租金）。

  • 如果余额 >= 租金免除门槛，则永远不被销毁（rent-exempt）。
  • 创建账户时要用 rent.minimum_balance(data_len) 来保证 rent 充足。

PDA

PDA 是程序根据一些种子 + 程序 ID 推导出来的一个“账户地址”，这个地址：

  • 没有私钥，不能被人签名
  • 只能通过程序使用 invoke_signed 写入
  • 是很多去中心化协议的“托管账户”

owner 权限、数据序列化、指令顺序

owner 权限

每个账户有个 owner 字段，标明：哪个程序可以修改它的数据。

  • 如果你不是 owner，就算是 signer 也不能改数据。
  • 常见错误：传入账户数据却无法写，是因为 owner 不对。

比如 SPL Token 的账户 owner 是 SPL Token 程序，你不能直接修改它的数据。

数据序列化（Borsh/Anchor）

Solana 的账户数据本质上是 byte array，你必须用某种方式序列化/反序列化。

  • Rust原生可以用 bytemuck 或 borsh
  • Anchor 会自动用 #[account] + #[derive(AnchorSerialize, AnchorDeserialize)] 封装结构体

这样 Anchor 会帮你把 byte array 映射成结构体。

指令顺序

在 Solana 中，一个 Transaction 中可以包含多个 Instruction，执行顺序必须自己控制。

  • 程序内部也可能有多个操作步骤（比如先创建账户，再初始化）
  • 如果顺序错了，就可能因为账户未初始化、未 rent 免除、权限不对等报错

CPI 调用的外部程序地址

1. sysvar::rent::id(), false

  • 称呼： Rent Sysvar（租金系统变量账户）
  • 作用： 提供 rent 信息，计算一个账户 rent-exempt（免租）所需 lamports。
  • 是否可写： ❌（只读）
  • 应用场景：
    • 创建账户时判断是否 rent-exempt
    • CPI 调用 initialize_account、create_account 时必须传入
    • Anchor 会自动要求传入 Rent<'_> 类型

2. solana_sdk::system_program::id(), false

  • 称呼： System Program（系统程序）
  • 作用： 创建账户、转账 lamports、分配空间等基本链上操作
  • 是否可写： ❌（只读）
  • 应用场景：
    • 使用 system_instruction::create_account 创建任意账户（包括 PDA）
    • Anchor 自动调用时（如初始化账户），也会要求传入
    • 所有 rent 帐号创建都依赖它

3. spl_token::id(), false

  • 称呼： SPL Token Program
  • 作用： Solana 官方的代币标准合约程序
  • 是否可写： ❌（只读）
  • 应用场景：
    • Token mint、transfer、burn、initialize_account 等操作
    • 所有与 SPL Token 相关的 CPI 都必须传入它

4. spl_associated_token_account::id(), false

  • 称呼： Associated Token Account Program（ATA 程序）
  • 作用： 创建并管理用户的默认 Token 账户（Associated Token Account）
  • 是否可写： ❌（只读）
  • 应用场景：
    • 调用 create_associated_token_account CPI 指令
    • 通常用于创建用户默认接收某个 mint 的 token 账户（如用户钱包 + mint 的唯一 token 地址）
